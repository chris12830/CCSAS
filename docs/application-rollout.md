# CC SAS cross-application rollout

CC SAS is the central advertising authority. Applications must fetch approved campaigns from the authenticated `GET /api/feed` endpoint; they must not manage independent supplier payments or trust browser-supplied API keys.

## Existing GitHub applications
- `child-care-owners-network`: Next/Vinext, add server-side feed adapter and render dashboard + resource-hub placements.
- `childcare-invoice`: Laravel, use server-side HTTP client with `X-SAS-App-Key`.
- `childcare-register-frontend`: Next.js, server-only feed adapter.
- `childcare-register-backend`: NestJS, optional server-side proxy.
- `Child-Care-Space-Planning`: repository has no application files.
- `childcare-clean`: empty repository.

## Configuration
Each application requires a unique integration key generated by CC SAS, stored only in server environment variables. Configure `CCSAS_BASE_URL` and `CCSAS_APP_KEY`; app ID must match the application registry in CC SAS. Never commit credentials. Do not show example campaigns in production.

## Operational safeguards
Feed calls are server-side and fail closed (no ads) on error. Verify country, audience, placement and enabled app settings in CC SAS. The existing `/api/events` endpoint records impressions/clicks and requires authenticated app calls. Do not deploy an ad ticker until rendering and event reporting are verified. Never expose key in HTML or client bundles.
